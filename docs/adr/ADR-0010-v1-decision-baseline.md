# ADR-0010 — V1 实施决策基线

- **状态** 已接受
- **日期** 2026-11-24
- **范围** 补充 ADR-0002 至 ADR-0009 在下列事项上的 V1 决策。

## 已确认的决策

| # | 事项 | V1 基线 |
|---|---|---|
| 1 | 微信应用凭据 | 密钥只存于密钥管理器，数据库保存 `credential_ref`。平台负责人管理授权，每 90 天轮换，泄露或相关人员变更时立即轮换。 |
| 2 | 第三方回调 | 有实际回调需求时，由 `game-api` 的独立 `/platform-callbacks/v1` 路由组承载，独立配置平台认证、限流和监控。V1 仅部署该承载方式。 |
| 3 | 激励广告 | V1 沿用服务端会话、过期校验、单次领取、每日限额、设备及行为信号，并限制奖励价值。V1 接受限额内仍可能作弊的风险，微信广告服务端验证留待后续评估。 |
| 4 | 战斗验证 | V1 使用服务端结算与轻量校验，不建设服务端回放验证。高价值玩法上线前须另行评估，并确定验证方案与奖励边界。 |
| 5 | GM 调账 | V1 由获授权的单个操作员执行，限制其游戏范围与发放、扣除权限，保留二次确认、必填原因、幂等与同事务审计。双人审批及其金额门槛留待后续增强。 |
| 6 | 数据保留 | 临时基线为原始事件 90 天、登录记录 180 天、审计记录 2 年、资产流水 7 年。账号关闭后按批准的规则删除或匿名化账号标识。发布前按目标市场确认最终期限及删除规则。 |
| 7 | 部署与恢复 | V1 单区域部署。初始恢复目标为 RPO 15 分钟、RTO 4 小时，须在发布前通过恢复演练验证。目标区域、数据驻留要求和峰值并发仍待确认。 |
| 8 | GM 令牌 | 强制 MFA。GM 访问令牌保留 15–30 分钟有效期，刷新令牌以哈希存储、使用时轮换并可撤销。刷新会话从首次签发起最长 7 天，轮换不延长该上限。 |
| 9 | RBAC 与数据库权限 | 最小权限、默认拒绝、按游戏授权。客服只读，封禁和解封交给获授权的游戏管理员。生产前采用受控数据库函数写入钱包和道具，运行时角色撤销对应表的直接变更权限。V1 依靠复合约束、应用范围校验、独立数据库角色和隔离测试，推迟 RLS。详见[权限矩阵](../security/rbac-matrix.md)和[数据库角色与授权](../database/database-roles-and-grants.md)。 |
| 10 | 会话与后台任务 | 玩家和 GM 启用刷新令牌重用检测及会话拒绝名单。任务默认租约 60 秒，每 20 秒续租，最多重试 5 次，退避从 10 秒到 15 分钟并加最多 20% 抖动，最终间隔不超过 15 分钟。批处理每批 500 人，空闲时每 2 秒轮询。 |
| 11 | V1 API 范围 | 纳入 GM 登出、MFA 注册、道具调账、非邮件批量奖励、活动与公告管理、排行榜创建与重建、任务查询及取消和重试，以及玩家邮件已读。详见[玩家 API 契约](../../api/openapi/game-api.yaml)、[GM API 契约](../../api/openapi/gm-api.yaml)和[实施路线图](../implementation/roadmap.md)。 |

## 仍需在相应门禁确认

- 生产发布前确认目标市场及其数据保留、删除、匿名化与驻留要求，记录目标区域和峰值并发。
- 高价值玩法上线前确认所需的战斗验证方式及奖励上限。
- 在 T03 验证数据库角色与隔离，在 T19 校验契约，在 T20–T22 完成恢复演练、运行时授权验证和负载验收。其余专题提案继续在对应阶段评审。
